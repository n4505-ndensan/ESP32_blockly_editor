# ADR 0009: 部品リストを画面から編集できる設定値にする

- ステータス: 採用
- 日付: 2026-10-05
- ADR 0001の「部品カタログは`devices.cpp`の表1か所で定義する」とする部分を置き換える。

## 背景

これまで部品の一覧は`src/devices/devices.cpp`の固定の表だけで、ピンを変えるにも部品を足すにも
ファームウェアの書き換えが必要だった。配布するキット（LED5色・ブザー・温度・距離）は同じピンで用意するが、
そこから部品を足したり、配線を変えたりすることはいつでも起こりうる。

## 決定

### 1. 部品リスト全体を1つの設定値として持つ

最初のキットの部品も、後から足した部品も、同じ形の行として扱う。
キットの8部品は「設定が保存されていないときの初期値」にすぎず、名前・ピンの変更も削除もできる。
「既定の部品」と「追加の部品」を分けると、配線の変更がキットの部品だけ反映できない、という制約を自分で作ることになる。

1行は`{id, type, label, pins}`で、`type`は`led` / `buzzer` / `thermo` / `tof`。
`pins`はLED・ブザーなら`[ピン]`、温度・距離センサ（I2C）なら`[SDA, SCL]`。
説明・単位・変化の判定幅などは種類から決まり、行には持たせない。

### 2. 保存先はNVS、反映は再起動で行う

部品リストはNVS（Preferences）に保存する。LittleFSは画面の更新（`uploadfs`）のたびに
イメージごと上書きされ、設定が消えるため使わない。

保存したらESP32を再起動して反映する。部品の表を動作中に差し替えると、
状態の配列・変化の印・実行中のプログラムが参照する部品番号を同時に更新する必要があり、排他の範囲が広がる。
再起動なら、起動時に全出力をOFFにそろえる流れ（ADR 0001 §6）と、bootIdの変化で画面がカタログを
取り直す流れをそのまま使える。実行中は保存を拒否する（409）。
保存してから再起動するまでの間は、プログラムの開始も409`restarting`で拒否する。

### 3. 部品IDは変えない

保存済みのブロックは部品IDで部品を指す。名前やピンを変えてもIDは変えない。
新しい部品のIDは`led_2`・`distance_2`のように種類ごとの名前に番号を付け、未使用の最小番号を使う。
登録済みの部品の種類は変えられない。種類を変えるとIDとブロックの対応が崩れるので、削除して追加し直す。

### 4. ピンの規則はファームウェアが正とする

使ってよいピン（候補ピン）はファームウェアが持ち、設定APIで配る。画面は同じ規則で先に問題を表示するだけで、
保存時にESP32が改めて検証する。候補から外すのは0・1・3（書き込み・シリアル）、6〜11（フラッシュ）、
12（起動電圧の切り替え）、34〜39（入力専用）。

ピンは1部品専用とする。例外として、SDA・SCLの組が同じI2C部品同士は同じバスに並べてつなぐものとし、
同じ役割（SDA同士・SCL同士）に限って共有を認める。同じバスに同じ種類のセンサは1個まで
（AMG8833・VL53L1Xとも、アドレスが固定のため）。

### 5. I2Cの組は2組まで

ESP32はI2Cを2系統持つので、SDA・SCLの組は2組までとし、組ごとに1系統（`Wire`・`Wire1`）を割り当てる。
組の番号は部品リストに初めて出てきた順に振る。各組に同じ種類のセンサは1個までなので、
温度・距離センサはそれぞれ最大2個になる。センサの組のピン自体は変更できる。
センサが1つも無いときはI2Cを開かず、SDA・SCLだったピンを他の部品に使える。

## 通信仕様

### `GET /api/settings/devices`

```json
{
  "candidatePins": [2, 4, 5, 13, 14, 15, 16, 17, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33],
  "parts": [
    { "id": "led_white", "type": "led", "label": "白色LED", "pins": [18] },
    { "id": "temperature", "type": "thermo", "label": "温度", "pins": [21, 22] }
  ]
}
```

返すのは起動時に読み込んだ（現在動いている）部品リスト。

### `POST /api/settings/devices`

本文は`{ "parts": [...] }`で、部品リスト全体を置き換える。成功時は200で`{ "restarting": true }`を返し、
約0.5秒後に再起動する。

| 状況 | ステータス | `error` |
| --- | --- | --- |
| JSONが壊れている、オブジェクトでない | 400 | `bad_request` |
| プログラムの実行中、または再起動待ち | 409 | `program_busy` / `restarting` |
| 規則に合わない（`message`に理由） | 422 | `invalid_settings` |
| NVSへ書けない | 500 | `save_failed` |

## 影響

- 部品の追加・ピン変更にファームウェアの書き換えが不要になる
- `GET /api/devices`のカタログは、保存された部品リストから起動時に組み立てる。カタログの形は変わらない
- 保存のたびに再起動するので、反映まで数秒かかり、出力はすべてOFFに戻る
- NVSを消去（`erase_flash`）すると最初のキットに戻る
