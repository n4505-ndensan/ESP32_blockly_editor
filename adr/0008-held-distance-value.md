# ADR 0008: 一部の測距失敗では鮮度内の直近正常値を使う

- ステータス: 一部置き換え済み（[ADR 0011](0011-wait-for-sensor-and-reconnect.md)）
- 日付: 2026-09-16
- ADR 0007の「無効な測距結果はすべてunavailable」とする部分、および状態の種類を一部置き換える。

## 決定

距離センサVL53L1Xの`WrapTargetFail`・`SignalFail`に限り、直前まで利用可能だった正常値があり、
最後の正常取得からの経過時間が1000ms未満なら、その値を`held`として使用する。
失敗した測定の数値は使わず、保存値と正常取得時刻は更新しない。許容対象の失敗が続いても期限を延長しない。
1000msちょうどから`stale`となる。

それ以外の測距異常や検出したI2C異常は即座に`unavailable`として無効化する。
正常値未取得時や、一度この即時無効化が起きた後は、許容対象の失敗が来ても過去値を復活させない。
新しい正常測定だけが値の利用を復旧し、正常取得時刻を更新して`ok`に戻す。
温度センサの異常は保持対象にしない。正常と認める測距ステータスはADR 0007の3種類から変更しない。

HTTP APIとSSEのセンサ状態は`{value: number | null, status: ok | held | unavailable | stale}`とする。
`ok`・`held`では数値、`unavailable`・`stale`では`null`を返す。
画面は`held`の数値と単位を`ok`と同じく表示する。
無効な値は従来どおり`--`と理由を表示する。ブラウザ独自の保持や期限延長は行わない。

実行器はセンサ式で`ok`・`held`を同じく数値として評価する。待機・一時中断・式のスキップは導入しない。
次にセンサ式がその値を読む時点で`stale`・`unavailable`なら、従来どおりそのブロックで実行エラーとし、
`allOff`で全出力をOFFにする。未使用のセンサや短絡評価で読まないセンサの異常だけでは停止しない。

## 理由と引き換え

一時的な特定の測距失敗で直ちに停止する代わりに、利用可能な直近正常値を既存の鮮度期限内だけ使う。
500msという別の猶予は導入せず、ADR 0007で既に採用した「最後の正常取得から1秒」を共通の上限にする。
これは本プロジェクトの鮮度方針であり、メーカーが保証した保持時間・確立した定数ではない。
異常発生から1秒を追加する方式でもない。

保持中は対象物の移動を値に反映できず、最大1秒未満の古い値で判断する可能性がある。
その制約を画面に明示し、即時無効化と正常測定による復旧を維持する。
診断ログは原因調査に引き続き使う。異常の根本原因が解消されたとみなす決定ではない。
