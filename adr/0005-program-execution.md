# ADR 0005: BlocklyのASTをESP32で実行する

- ステータス: 採用
- 日付: 2026-09-15

## 決定

Blocklyの開始ブロックにつながる1本の処理を、バージョン付きの実行用ASTに変換し、HTTPでESP32に送る。
ESP32は型・部品・数値範囲・容量を再検証してからRAMに保持する。編集用JSONや生成JavaScriptは実行しない。
変数・関数・並行実行・保存復元・自動起動は今回扱わない。

待機や無限ループ中も通信とセンサ取得を進めるため、検証済みASTを内部命令列にし、
`loop()`から最大64命令または1msずつ実行する。式の評価も分割対象にする。
待機はミリ秒の経過差で判定し、待機0も次のtickまで処理を譲る。

ブラウザを閉じても実行を続ける。別の画面や再接続した画面は、実行状態のスナップショットを取得して停止できる。
実行開始時には出力だけをOFFにし、正常終了時は最終状態を保持する。停止・実行エラーでは全出力をOFFにする。

## 境界

- JSON 32KiB、AST 256ノード、AST深度16、blockIdはUTF-8で64バイトまで。
- JSON解析深度64、解析中の割り当て96KiB、同時受信2件まで。確保できなければ503で拒否する。
- 数値は有限のdouble、真偽値との暗黙変換なし。AND/ORは短絡評価。
- 待機ミリ秒・繰り返し回数は0〜2147483647の整数。回数はループ入口で一度評価する。
- ifのelse-ifとuntilは、入れ子のifと否定付きwhileに変換する。
- ノードのblockIdをエラーへ引き継ぐ。実行時と編集内容が一致する画面だけでエラー位置を強調する。

## 検証

VitestでBlockly変換とクライアント状態を先にテストし、C++の実行器はUnityで検証する。
`shared/program-fixtures.json`を両側で使い、時計・部品は実行器の外から渡す。
実機のHTTP APIとブラウザからの接続も検証する。
